# 需求：LumaMark 跨浏览器书签

日期：2026-10-28

## 一屏摘要

- 目标：做一个独立、现代化、可迁移的个人书签产品，让用户快速保存、整理和重新找到网页链接（R1、R2）。
- 使用者：不希望把书签绑定到 Google 账号或单一浏览器的个人用户（R1、R3）。
- 范围：Chrome、Edge、Firefox 扩展；Safari macOS 扩展；扩展入口与书签库页面；本地优先存储；WebDAV 自托管同步（R1–R5）。
- 关键行为：离线可用；同步失败不影响本地数据；同步冲突可见并可处理；数据可导入、导出和迁移（R3、R4）。
- 成功标准：用户能一键保存当前页，在书签库中用搜索、集合、标签和多视图找到它，并在不同浏览器间通过导入导出或自己的 WebDAV 保持一致（R1–R5）。
- 不做事项：首发不接 Google 账号或官方云同步，不做移动 Safari、S3/自有服务同步实现、团队协作、社交分享和网页全文归档（R6–R10）。

## 完整需求

### R1 跨浏览器快速保存

行为：用户在 Chrome、Edge、Firefox 或 Safari macOS 的网页上点击扩展按钮、使用右键菜单或快捷键时，LumaMark 保存当前页面的 URL、页面标题和站点图标，并允许用户选择集合、添加标签和备注。保存完成后显示明确的成功反馈，并提供打开书签库或撤销的入口。

适用与失败边界：只在用户主动触发时读取当前页面信息；无法读取标题或图标时仍保存 URL，并使用可编辑的默认标题或站点域名。若当前 URL 已存在，必须提示已有记录并提供打开、更新元数据或仍然保存副本的选择，不得静默制造重复项。

验收：

- 在四类目标浏览器中从普通网页触发保存，书签库能看到相同 URL，且集合、标签和备注可在保存时填写。
- 在标题或图标抓取失败、页面无网络或 URL 已存在时，保存流程仍有可理解的结果和下一步操作。
- 用户点击撤销后，刚保存的记录从当前列表消失，并可通过提示恢复。

### R2 书签库的组织与检索

行为：书签库页面提供集合/文件夹、标签、域名和时间筛选，支持搜索标题、URL、标签和备注；提供网格、列表和紧凑视图；支持排序、拖拽移动、批量编辑、批量删除、收藏标记和最近保存入口。扩展弹窗提供快速搜索和最近保存项，并能打开完整书签库。

适用与失败边界：搜索和筛选组合为空时显示可行动的空状态，并允许清除条件；集合、标签或书签删除前说明影响并支持撤销或恢复；大列表加载时显示渐进式加载状态，不以空白页面代替加载或错误状态。

验收：

- 给定一组含不同集合、标签、域名和备注的书签，输入标题、域名或备注关键词均能得到对应结果，组合筛选只保留同时满足条件的记录。
- 切换三种视图或排序方式不会改变书签内容；拖拽或批量移动后，记录在目标集合中可见。
- 删除记录后可在回收站或撤销入口恢复；清空搜索和筛选后回到完整列表。

### R3 本地优先与可携带数据

行为：用户无需注册或登录即可完成保存、编辑、搜索、分类、删除和打开书签。核心书签数据在本地可用；浏览器离线或远端同步不可用时，已有数据和本地编辑继续可用。用户可以导入浏览器标准 HTML 书签和 LumaMark JSON 备份，也可以导出完整数据。

适用与失败边界：导入过程中发现重复 URL、无法解析的节点或损坏文件时，保留可解析内容，报告跳过项并允许用户取消；导出失败时不删除或修改本地数据。卸载或清除扩展前必须能从设置中找到导出入口和数据说明。

验收：

- 首次打开产品不登录也能保存并搜索书签；断网后重复打开仍能查看和编辑已有记录。
- 导入 Chrome、Edge、Firefox 或 Safari 导出的标准 HTML 文件后，文件夹层级和 URL 可用；重复项有明确处理结果。
- 导出的 JSON 可在另一份干净安装中恢复，恢复后的标题、URL、集合、标签、备注和收藏状态一致。

### R4 WebDAV 自托管同步

行为：用户可在设置中配置 WebDAV 地址、目标路径和凭据，手动执行同步，并可选择启用自动同步。界面显示连接状态、最近同步时间、待同步变更、失败原因和重试入口。同步数据只发送到用户配置的远端，不要求 LumaMark 账号或 Google 账号。

适用与失败边界：网络中断、地址不可达、认证失败、远端只读或空间不足时，本地数据继续可用，未同步变更保留在本地并可重试；检测到同一记录在本地和远端均被修改时，不能静默覆盖，必须展示冲突版本并让用户选择保留内容。凭据无效时不得反复后台重试造成干扰。

验收：

- 使用可写 WebDAV 目录配置两台浏览器实例，新增、编辑和删除书签后手动同步，另一实例能看到对应变更。
- 断网或输入错误凭据时，页面显示可理解的错误与重试操作，本地新增书签仍可搜索和导出。
- 人为制造同一条记录的本地/远端不同修改时，界面展示冲突并允许选择版本，选择结果可再次同步。

### R5 现代化、实用且可访问的交互体验

行为：扩展弹窗负责快速保存和快速查找，书签库页面负责深度管理；首屏优先展示搜索、最近保存、常用集合和同步状态。界面提供清晰的空状态、加载状态、错误恢复、撤销反馈和危险操作确认，并支持明暗主题、响应式布局、键盘操作、可见焦点和语义化标签。

适用与失败边界：关键操作不能只依赖悬停或无文字图标；在窄窗口或较长标题、域名、标签下不得出现横向溢出或操作被遮挡。动画或装饰不能阻塞保存、搜索、打开和同步等核心流程。

验收：

- 新用户从扩展入口能在一个连续流程内完成保存，并能从反馈直接打开刚保存的记录。
- 在桌面宽窗口、窄弹窗和深色主题下，搜索、保存、编辑、删除、同步和错误恢复入口均可见且可操作。
- 仅使用键盘完成搜索、打开、编辑、确认和取消操作时，焦点顺序清晰，当前焦点可见，读屏可获得控件名称和状态。

### R6 浏览器交付与兼容边界

行为：首发交付 Chrome、Edge、Firefox 的扩展包，以及 Safari macOS 可安装的扩展包或应用扩展包装；四类浏览器共享书签数据模型和核心交互语义，并分别提供安装、权限和更新说明。

适用与失败边界：浏览器不支持某项扩展能力时，产品必须提供等价替代入口或明确说明限制，不得让核心保存和书签库不可用。Safari macOS 的分发依赖 Apple 的扩展包装与审核流程，因此安装方式、权限提示和更新方式可与 Chromium/Firefox 不同。

验收：

- 四类浏览器均能安装并完成当前页保存、打开书签库、搜索和导出。
- 同一份导出数据可在另一类浏览器导入，核心字段和集合层级保持一致。
- 安装文档明确列出所需权限、数据去向、Safari macOS 的包装方式和不支持的浏览器能力。

## 不做事项

### R7 不接入 Google 账号或浏览器厂商同步

行为：首发版本不得要求用户登录 Google、Chrome、Edge、Firefox 或 Apple 账号来使用核心功能，也不把浏览器厂商的同步服务作为唯一数据来源。

适用与失败边界：浏览器自身是否登录不影响 LumaMark 的本地保存、搜索、导入和导出；产品不得因用户未登录厂商账号而阻断核心流程。

验收：

- 未登录任何浏览器账号时，核心功能仍可完成。
- 设置和隐私说明中不存在把厂商账号作为必需条件的流程。

### R8 首发不实现 S3 或自有服务同步

行为：首发只交付 WebDAV 同步；S3 兼容存储和自有服务 API 只保留未来适配的产品边界，不出现在首发可用配置中。

适用与失败边界：用户选择未支持的同步方式时，界面明确标注“后续支持”或导出数据供用户自行迁移，不得伪装成已可用。

验收：

- 首发同步设置只显示 WebDAV 配置和状态。
- 需求、帮助文档和发布说明不把 S3 或自有服务描述为已交付能力。

### R9 首发不做移动 Safari、团队协作和社交分享

行为：首发不交付 iOS/iPadOS Safari 扩展、共享集合、成员权限、评论、公开页面或社交发现。

适用与失败边界：用户在移动 Safari 或需要协作时，产品提供清晰的范围说明和可导出的数据，不进入半可用的协作流程。

验收：

- 支持矩阵将 Safari macOS 与 iOS/iPadOS 明确区分。
- UI 中没有未实现的成员、分享或公开访问入口。

### R10 首发不做网页全文归档

行为：首发只保存 URL 和用户可编辑的页面元数据、标签与备注，不保存网页全文、截图、PDF 副本或永久快照。

适用与失败边界：网页下线或需要离线阅读不属于首发保证；界面不能暗示用户拥有网页内容副本。

验收：

- 书签详情和隐私说明明确区分“链接收藏”和“网页归档”。
- 导出内容不包含未声明的网页正文或截图副本。

## 来源

- [Raindrop.io 产品页](https://raindrop.io/)：支持 R1、R2 中的集合、标签、过滤、多视图、批处理、导入导出和跨浏览器访问判断。
- [Firefox Bookmarks Help](https://support.mozilla.org/en-US/kb/bookmarks-firefox)：支持 R2、R3 中的标签、搜索、排序、拖拽、备份、导入和导出判断。
- [Chrome Bookmarks Help](https://support.google.com/chrome/answer/188842?hl=en-GB_ALL)：支持 R2、R3 中的文件夹、排序、拖拽和浏览器 HTML 迁移判断。
- [Apple Safari Web Extensions](https://developer.apple.com/documentation/safariservices/safari-web-extensions)：支持 R6 中 Safari macOS 需要 WebExtension 包装、权限和分发边界的判断。
- [Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)：支持 R3、R7 中浏览器原生同步容量有限、不能作为完整跨浏览器数据层的判断。
- 用户在本次需求中明确的约束：不依赖 Google 账号；支持跨浏览器；本地优先；用户自托管同步；WebDAV 首发；Safari macOS 首发。

- WebDAV 凭据保存方式、数据加密格式和冲突合并的具体交互稿尚未确定：不改变当前行为要求，将在技术方案和 UI 设计阶段细化。
